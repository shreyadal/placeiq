# data/

Two csv files: a cleaned public dataset of student answers, and simulated interview logs
in PlaceIQ's own format. Both are meant for the knowledge tracing model that is planned next.
[prepare.py](prepare.py) turns each of them into model-ready files, described in
[Model-ready files](#model-ready-files) below.

| file | rows | what it is |
|---|---|---|
| `assistments2009_cleaned.csv` | 283,105 | real student answers to maths problems, cleaned |
| `interview_simulated.csv` | 17,851 | simulated interview answers, not from real people |

Row counts exclude the header line.

## assistments2009_cleaned.csv

**Source.** ASSISTments 2009-2010 Skill Builder data, file
`skill_builder_data_corrected_collapsed.csv`, from
<https://sites.google.com/site/assistmentsdata/home/2009-2010-assistment-data/skill-builder-data-2009-2010>.
The raw file has 346,860 rows and 30 columns.

**Cleaning done.**

1. Read as latin-1 and saved as UTF-8 (the raw file has a few bytes that are not valid UTF-8).
2. Dropped rows with no `skill_id`: 63,755 rows. No row was missing `user_id`,
   `problem_id`, `correct` or `order_id`. 346,860 - 63,755 = 283,105 rows remain.
3. Kept 6 of the 30 columns (below).
4. Ordered rows by student, and by `order_id` within a student, so each student's rows
   read top to bottom in the order they answered.

**Columns.**

| column | type | meaning |
|---|---|---|
| `user_id` | int | student |
| `order_id` | int | id of the answer; increases with time |
| `problem_id` | int | problem that was answered |
| `skill_id` | string | skill the problem tests. A problem with several skills has them joined by `_`, e.g. `1_13` |
| `skill_name` | string | name of the skill, as given in the source. Empty in 8,515 rows |
| `correct` | 0 or 1 | 1 if the first attempt was correct |

**Counts.**

| | |
|---|---|
| rows (answers) | 283,105 |
| students | 4,163 |
| problems | 17,751 |
| skills | 123 (149 distinct `skill_id` values, counting combinations) |
| rows with more than one skill | 47,037 |
| share answered correctly | 65.8% |
| answers per student | median 20, mean 68, max 1,061 |

## interview_simulated.csv

**Source.** Generated by a simulator, because PlaceIQ has no real users yet. Each of 400
simulated candidates gets a hidden ability per concept. The chance of a good answer rises
with that ability and falls with the question's difficulty, and ability grows slightly
with every attempt. Questions are drawn from a bank of 102 interview questions. The
simulator and the question bank are not in this trimmed version of the repo.

No cleaning was needed; no value is missing.

**Columns.**

| column | type | meaning |
|---|---|---|
| `user_id` | string | simulated candidate, `u0001` to `u0400` |
| `question_id` | string | id of the question in the question bank, e.g. `cn-008` |
| `concept` | string | DSA, OS, DBMS, CN, OOP or ML |
| `score` | float, 0 to 1 | how good the answer was |
| `timestamp` | int | time of the answer, unix milliseconds (simulated, June to September 2025) |

**Counts.**

| | |
|---|---|
| rows (answers) | 17,851 |
| candidates | 400 |
| questions | 102 |
| concepts | 6, between 2,882 and 3,057 rows each |
| mean score | 0.52 |
| answers per candidate | median 45, min 19, max 73 |

## Model-ready files

`python data/prepare.py` (needs `pip install pykt-toolkit pandas`) reads the two csv files
above and writes `assist2009/` and `interview/`. It uses
[pykt](https://github.com/pykt-team/pykt-toolkit)'s own functions, so the files are in the
format pykt's models train on. Three things happen:

1. **One sequence per student.** `data.txt` holds six lines per student: id and number of
   answers, question ids, concept ids, responses, timestamps, time spent (`NA` where the
   dataset has no such field). Answers are in time order.
2. **Responses become 0 or 1.** ASSISTments already has `correct`. An interview `score`
   of 0.5 or more counts as 1, otherwise 0; 53.9% of interview answers are 1.
3. **Students are split.** 20% of students are held out for testing and the other 80% are
   divided into 5 folds for cross-validation. The split is by student, so no student is in
   both. It uses a fixed seed, so running the script again gives the same files.

Along the way students with fewer than 3 answers are left out, raw ids are replaced by
indices starting at 0 (the mapping is in `keyid2idx.json`), and an ASSISTments answer
tagged with several skills becomes one row per skill, with the extra rows marked
`is_repeat = 1`.

| | `assist2009/` | `interview/` |
|---|---|---|
| students in the cleaned csv | 4,163 | 400 |
| left out (fewer than 3 answers) | 311 students, 486 answers | none |
| students kept | 3,852 | 400 |
| answers kept | 282,619 | 17,851 |
| `train_valid.csv` students | 3,082 (folds of 617, 617, 616, 616, 616) | 320 (5 folds of 64) |
| `test.csv` students | 770 | 80 |
| questions / concepts | 17,737 / 123 | 102 / 6 |

In `train_valid.csv` and `test.csv` each row is one student, and every cell except `fold`
and `uid` is a comma-joined list with one entry per answer.

| column | meaning |
|---|---|
| `fold` | 0 to 4 in `train_valid.csv`, -1 in `test.csv` |
| `uid` | student index |
| `questions` | question indices |
| `concepts` | concept indices |
| `responses` | 0 or 1 |
| `timestamps` | unix milliseconds (interview only) |
| `is_repeat` | 1 for the extra rows of a multi-skill answer, else 0 |
| `cidxs` | running number of the answer across the whole file (`test.csv` only) |

Because of the extra multi-skill rows, the ASSISTments lists hold 337,424 entries
(274,614 train and validation, 62,810 test) for 282,619 answers.
